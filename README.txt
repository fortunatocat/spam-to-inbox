Письма из «Спама» во «Входящие»
================================

Python 3.10 или новее. Windows, macOS, Linux. Дополнительные библиотеки не нужны.
Скрипт запускается на вашем компьютере, не отправляет статистику или данные
сторонним сервисам. Подключается к серверам почты, указанным вами в конфиге.

Важная разница
-------------
POP3 обычно показывает только входящие и не позволяет выбирать папку «Спам».
Поэтому перенос выполняется через IMAP. Раздел pop3 в конфиге нужен только
для отдельной проверки числа писем во входящих: команда --check-pop3.
Доступ к IMAP необходимо включить в настройках почты. Если провайдер требует
пароль приложения, используйте его. OAuth-вход в этой версии не поддержан.
Провайдеры, запрещающие парольный IMAP-вход, потребуют другого клиента.

Первый запуск
-------------
1. Скопируйте config.example.json в config.json.
2. Скопируйте accounts.example.txt в accounts.txt и замените содержимое своей
   пачкой ящиков. Можно указать один ящик, 100 или больше — отдельной настройки
   количества не требуется. На строке только логин и пароль:
   you@example.com:ВАШ_ПАРОЛЬ
   other@example.com:ДРУГОЙ_ПАРОЛЬ
   Поддерживаются также разделители точка с запятой и табуляция. Разделяется
   только первый разделитель, поэтому двоеточие внутри пароля сохраняется.
   Пустые строки и комментарии, начинающиеся с #, пропускаются. Файл — UTF-8,
   в том числе с BOM. Полные одинаковые записи обрабатываются один раз;
   один логин с разными паролями считается ошибкой до сетевых запросов.
3. Один раз задайте host, port и security в общих разделах imap/pop3 конфига.
   Эти параметры применяются ко всем ящикам из accounts.txt. Обычно одна пачка
   принадлежит одному провайдеру и использует одинаковые серверы.
   Данные сервера и способ входа берите в справке своего почтового провайдера.
   Для обычного IMAP через SSL: port 993, security "ssl".
   Для POP3 через SSL: port 995, security "ssl".
   Поддерживается также "starttls": обычно порты IMAP 143 / POP3 110.
   Отключение TLS и проверки сертификатов не предусмотрено.
   Файл accounts.txt содержит ваши пароли: не публикуйте и не пересылайте его.
   Пример в раздаче вымышленный; готовых настоящих ящиков в комплекте нет.
4. Сначала проверьте без перемещения:
   python mail_spam_rescue.py --config config.json --dry-run
5. Для одного прохода с переносом:
   python mail_spam_rescue.py --config config.json
6. Для повторения через заданный интервал после завершения прохода:
   python mail_spam_rescue.py --config config.json --loop
   В Windows можно запустить start.cmd из той же папки.
   Остановка — Ctrl+C. Компьютер должен оставаться включённым.

В Windows вместо python можно писать py -3.
Проверка POP3: python mail_spam_rescue.py --config config.json --check-pop3
Она выполняет STAT, не скачивает и не удаляет письма.

Настройки
---------
days — период поиска по календарной дате IMAP SINCE, не точные последние N*24 часа.
interval_seconds — пауза между проходами, минимум 60 секунд.
threads — одновременно проверяемые ящики, от 1 до 8; по умолчанию 2.
Это ограничение параллельности, не размера пачки. Все строки будут перебраны,
ошибка одного ящика не мешает проверке остальных; в следующем проходе
проверяется вся пачка снова. Вывод показывает номер ящика и итог ошибок.
timeout_seconds — таймаут одной сетевой операции, не всего прохода.
accounts_file — путь к файлу login:password. Относительный путь считается
от папки config.json, независимо от того, из какой папки запущена команда.
Можно указать файл поставщика по полному пути, не копируя и не изменяя его.
Файл перечитывается при старте программы; после изменения пачки перезапустите её.
spam_folders — возможные имена папки: выбирается первая существующая.
Если папка не найдена, укажите точное имя из настроек вашего IMAP-клиента.
Поддерживаются имена кириллицей и другие национальные алфавиты.
inbox_folder — папка назначения; обычно INBOX.

Для нескольких провайдеров используйте отдельные папки/конфиги. Совместимость
со старым расширенным JSON accounts сохранена, но одновременно задавать
accounts_file и accounts нельзя. Общую папку state-dir для разных конфигов
менять не обязательно: она также защищает от одновременного запуска.

Как происходит перенос
----------------------
Переносятся все неудалённые письма указанного периода из выбранной папки,
а не только письма какого-либо отправителя. Убедитесь, что вам нужен именно
такой порядок обработки спама: рекламные письма тоже попадут во входящие.

При наличии расширения MOVE используется UID MOVE. Иначе нужен UIDPLUS:
UID COPY -> UID STORE -> UID EXPUNGE только выбранного письма. Общий EXPUNGE
не вызывается. Если сервер не поддерживает ни MOVE, ни UIDPLUS, скрипт
откажется от переноса; подсчёт --dry-run всё равно доступен.
Успех засчитывается после положительных ответов сервера. При частичной ошибке
число завершённых переносов сохраняется, ошибка показывается отдельно.

После успешного COPY, если завершение переноса прервалось, локальный журнал
позволяет повторить удаление исходника без повторного копирования. При потере
ответа COPY или сбое до записи журнала остаётся окно неопределённости: гарантия
отсутствия дублей для серверов без MOVE не предоставляется.
Не запускайте несколько копий программы с разными state-dir на один ящик.

Журнал незавершённых операций и блокировка находятся вне папки раздачи:
Windows: %LOCALAPPDATA%\SpamToInbox
macOS/Linux: ~/.local/state/SpamToInbox
Можно задать другую папку параметром --state-dir.
Незавершённый журнал не удаляйте до успешного повторного прохода.
В вывод не включаются пароль, адрес ящика и необработанные ответы сервера.
Код завершения: 0 — без ошибок, 1 — ошибка ящика/переноса, 2 — ошибка конфига.
Для планировщика запускайте один проход без --loop с нужным вам интервалом.
